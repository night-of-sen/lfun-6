## 一、这次做了什么

原网站是纯静态单页工具：起盘、分类、详细解读全部在浏览器里算，零收入、无用户概念、无服务端。
本次改造在**不动起盘算法**的前提下，把「详细解读」变成可付费的增量内容，并补齐订单、会员、云同步、打赏与分享回流。

### 付费墙怎么切（最关键的设计决定）

| | 内容 | 位置 |
| --- | --- | --- |
| **免费层（永远免费）** | 六宫罗盘、三宫名称、简版断语、计算公式与使用约定、分享卡片 | 仍由 `dist/app.js` 本地计算渲染 |
| **付费层** | 起盘三步详解、日时组合断语、分类专断、发展过程/节奏/着眼点/应验信号、寻物专断、心理与情绪、解卦语、行动建议 | 由服务端 `POST /api/unlock` 下发 |

- 免费层零改动、离线可用：断网也能起盘、也能生成分享卡片。
- 付费层**由服务端权威生成**：文案库在服务端，前端只负责渲染；后台改文案立刻生效，无需重新部署。
- 未付费访问 `/api/unlock` 返回 **402**，且响应体里不含任何解读文本（已在测试中断言）。

### 新增「日宫 × 时宫」组合断语（付费层的主要内容增量）

按传统小六壬「日上起时」的 36 组掌诀，为 9 类问题分别成文：

| 语言 | 文件 | 条目 |
| --- | --- | --- |
| 中文 | `dist/api/data/deep.zh.php` | 8 类 × 36 = 288 条 |
| 英文 | `dist/api/data/deep.en.php` | 8 类 × 36 = 288 条 |
| 寻物 | `dist/api/data/overrides.zh.php` | 补齐 7 个空格，36 组全覆盖 |

所有 324 个「类别 × 日宫 × 时宫」组合都有内容，无空白（`tests/verify-content.php` 逐条断言）。

## 三、怎么上线（Hostinger）

1. 把 `dist/` 里的**全部内容**上传到 `public_html`（不要多套一层目录）。
2. 复制 `api/config.local.php.example` 为 `api/config.local.php`，填写：
   - `app.install_token`：一段随机字符串（安装与后台签名都用它，务必改掉）
   - `db`：Hostinger 的 MySQL 连接信息（M2 云同步建议用 MySQL；也可先用 SQLite）
   - `admin.username / admin.password`：后台账号
   - `pay.manual.wx_qr / alipay_qr`：收款码图片（放到 `dist/media/` 后填相对路径）
3. 浏览器打开 `https://lfun.cloud/api/install.php?token=你设置的 install_token`。
4. **删除 `api/install.php`**。
5. 打开 `https://lfun.cloud/api/admin/` 登录后台，改定价、看订单。

详细步骤见 `docs/部署指南-Hostinger.md`。

### 收款方式：人工收款作为正式路径（PRD §0 A1）

**站长已确认目前没有微信/支付宝商户号，因此人工收款不是临时兜底，而是正式收入路径。**
这条路径已按「不需要站长盯后台」的目标打磨：

| 环节 | 现在的行为 |
| --- | --- |
| 下单 | 用户看到收款码 + 订单号；未配置收款码时明确提示「请联系站长」 |
| 用户付款后 | 点「我已完成付款」；**站长手机立刻收到推送**（企业微信/钉钉/飞书/Server酱/Bark） |
| 等待期间 | 页面明确写出「通常 N 分钟内开通」「超时联系谁」「可关闭窗口后从『我的』查看」，不让用户干等 |
| 站长在后台 | 顶部红色横幅「有 N 笔订单用户已点『我已付款』」+ 一键跳转；订单页每 60 秒自动刷新 |
| 核销 | 点「确认收款并开通」→ 用户端刷新即解锁（幂等，重复点不会重复入账） |
| 超时兜底 | 「我的」页随时可查订单状态；购买须知与等待页都带客服联系方式 |

**强烈建议配置站长通知**（`config.local.php` 的 `notify` 段）：

```php
'notify' => [
    'enabled' => true,
    'type'    => 'wecom',   // wecom | dingtalk | feishu | serverchan | bark | generic
    'url'     => 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxx',
    'secret'  => '',        // 钉钉加签时才需要
    'on'      => ['claim' => true, 'paid' => false, 'donation' => true],
],
```

配好后在后台「分享回流 / 运维」→「发送测试通知」验证一次即可。

拿到商户号后，把对应渠道 `enabled` 打开并填入密钥即可切换为自动核销，
代码已按官方规范实现签名、回调验签（RSA2 / APIv3）、金额校验与幂等。

## 五、已知限制与后续建议

1. **微信/支付宝适配器未与真实商户号联调**。签名与验签逻辑已实现并可在有凭证时直接启用，
   但端到端只能在拿到 MCHID/证书后验证。**建议先用人工收款跑通，再灰度切支付接口。**
2. ~~客户端仍保留旧版详细文案表~~ —— **已完成（本次收尾）**。
   详细解读文案（`INSIGHTS`、`TOPIC_READINGS`、`CATEGORY_ENDINGS`、`EMOTIONAL_READINGS`、`PALACE_PACE`、`PALACE_ACTIONS`、
   `VERIFY_SIGNALS`、`LOST_BASE`、`LOST_COMBOS` 及英文站对应表）与只服务于付费层的函数、观察器已全部从
   `dist/app.js` / `dist/en/app.js` 移除，客户端只剩免费层所需数据。
   手术脚本：`tools/strip-client-paid-content.js`（可 `--check` 复核，写盘前做语法自检）；
   校验：`tools/check-client-leak.js` 逐条断言付费文案不在客户端、免费层数据仍在。
   体积：中文 33.9K → 14.4K 字符，英文 20.5K → 10.1K 字符。
3. **本环境无法启动真实浏览器**（沙箱禁止 Chrome 的命名管道 IPC），
   因此前端用 jsdom + 真实后端做了端到端验证；上线前仍建议按 `docs/验收清单.md` 在真机走一遍。
4. **人工收款需要人工核销**。已用「支付推送 + 后台横幅 + 自动刷新 + 超时客服兜底」把人工成本压到最低；
   若仍想完全免人工，可在后台把「自动开通」打开（`pay.manual.auto_grant=true`），
   但用户只要点一下「我已付款」就会拿到内容，存在被白嫖的风险，默认关闭。
5. **退款流程为 v1 人工退款**（后台点退款 → 状态 refunded 并收回解锁）。
6. 数据库默认 SQLite；生产建议 MySQL（Hostinger hPanel 一键创建），并配置定期备份。

### 回滚方案（PRD §8 要求）

- 三级回滚，从轻到重：
  1. 后台 →「定价与开关」→ 关闭**付费墙**开关。站点立即回到「详细解读免费」，所有已付费订单不受影响。
  2. `git revert` 本次提交并重新上传 `dist/`（前端 `index.html` 只多了两个 `<link>/<script>`，删掉即恢复原样）。
  3. 删除 `dist/api` 目录，站点行为与原版完全一致（原有功能不依赖后端）。
- 数据不会被破坏：所有新表都是 `CREATE TABLE IF NOT EXISTS`，不影响既有文件。
